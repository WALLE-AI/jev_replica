# NanoJev 模型架构与训练复现报告

## 一、基础模型

**Qwen3-0.6B** 加一个自定义的决策头(Decision Head),组成 `DecisionPredictor` / `DecisionModel`。

### Backbone 结构(标准 decoder-only Transformer)

来自 `backbone_config/config.json`:

| 参数 | 值 |
|---|---|
| 层数 | 28 |
| hidden_size | 1024 |
| attention heads / KV heads | 16 / 8(GQA,分组查询注意力) |
| head_dim | 128 |
| FFN 中间维度 | 3072(SwiGLU 激活) |
| RMSNorm eps | 1e-6 |
| RoPE theta | 1,000,000 |
| 最大位置编码 | 40,960 |
| 词表大小 | 151,936 |
| embedding 绑定 | tie_word_embeddings=true |

用 `transformers.AutoModelForCausalLM.from_pretrained` 加载,但只取 `last_hidden_state`,不使用其自带的语言模型头——模型只作为文本编码器使用。

### 输入构造(一次前向打分所有候选)

对每个"问题"(state + question + 候选集合),编码成共享前缀 + 不同候选后缀的完整序列:

```
State:
{当前状态文本}
Question type: {boolean|choice|score}
Question:
{问题指令}
[Boolean 专属: False criterion: ... / True criterion: ...]
Candidate:
{候选具体文本}
Decision:<eos>
```

- 每个候选是独立完整序列(当前实现不做 KV cache 前缀共享,是"brute-force"重算)。
- 一批候选统一 padding 后一次性喂给 backbone,取每条候选序列最后一个 token(EOS)位置的 hidden state 作为该候选表示。这是"并行决策"的具体实现:一次 forward 同时给所有候选打分,不做自回归生成。

### 决策头(Decision Head)结构

```
Qwen3 backbone (28层, hidden=1024)
        │  取每条候选最后一个 token 的隐状态
        ▼
   LayerNorm(1024)                         ← self.norm
        │
        ▼
   Linear(1024 → 1)  ─────────────► 基础标量分数 z_base   ← self.scalar (std=0.02 初始化)
        │
        │ 仅 Choice 类型问题走"集合注意力"分支:
        ▼
   [h ‖ log(候选数k)] → Linear(1025→128)   ← self.set_project
        ▼
   MultiheadAttention(128维, 4头, batch_first) 候选之间互相看  ← self.set_attention
   (key_padding_mask 屏蔽 padding 候选)
        ▼
   tanh(u + attn输出) → Linear(128→1) = Δz  ← self.set_output (权重/偏置初始化为0)
        ▼
   z_choice = z_base + Δz
```

三种问题类型最终变成概率的方式:

| 类型 | 处理方式 |
|---|---|
| Boolean | 只编码"命题为真"这一句候选文本,得标量 z;固定 `logits=[0, z]` 做 2 类 softmax,等价 `p_true=sigmoid(z)`。不需要单独编码"假"文本。 |
| Choice(2~255 个动态候选) | 每候选独立算 `z_base`,再叠加集合注意力精修的 `Δz`,softmax 得完整分布。 |
| Score(2~10 个有序等级) | 与 Choice 类似算 `z_base`,但不经过集合注意力头,直接 softmax;期望值 = Σ(等级序号 × 概率)。 |

细节:`set_output` 权重/偏置初始化为全 0,保证训练刚开始 Choice 分支贡献为 0(恒等残差旁路),不扰乱热启动的基础打分能力;`scalar` 层用 std=0.02 正态初始化避免第一步梯度为零;无效/padding 候选 logit 填 `-1e9`。

## 二、数据集构建

四类任务、hard/soft 两种目标版本,每种版本共 **18,760 条决策问题**,train/dev/calibration/test/ood 五个分区:

| 任务 | 五分区合计 | 训练分区 | 数据来源 |
|---|---:|---:|---|
| Maze | 1,469 | 651(有效) | Jev 引导采集(付费闭源 API) |
| Snake | 958 | 400(有效) | Jev 引导采集(付费闭源 API) |
| ViZDoom Basic | 5,160 | 3,054 | Jev 引导采集(付费闭源 API) |
| ViZDoom Predict Position | 11,173 | 6,788 | Sonic Doom 专家策略蒸馏(hard=one-hot 最高概率动作,soft=完整分布) |

数据集已连同标签一起发布在 HuggingFace(`C-Tianyu/NanoJev-Data`,revision `unified-games-v1`),因此复现训练**不需要重新调用 Jev API 或获取 Sonic Doom 专家权重**——这是绕开两个黑盒依赖的关键。

## 三、训练流程

### 优化器与损失

- `torch.optim.AdamW`,两组不同学习率:backbone 一组、decision head(LayerNorm+Linear+注意力)一组(head lr 通常是 backbone 的 10 倍),`weight_decay=0.01`,梯度裁剪到全局范数 1.0。
- SFT 阶段用标准交叉熵 `-Σ target(a)·log softmax(logits)(a)`,target 为 one-hot gold 或 teacher 软概率分布。
- 参数以 fp32 主副本存储,前向用 `autocast(dtype=bfloat16)`,配合 gradient checkpointing。
- 每次更新固定采样 Maze 8 + Snake 8 + Basic 4 + Predict Position 4 共 24 题,loss 按 1/3、1/3、1/6、1/6 加权,四任务共用同一套 backbone+decision head 参数。

### 四臂 SFT 对比与选型(本次复现执行的内容)

官方实验对比 hard/soft 目标 × backbone lr 1e-5/2e-5 共 4 个 arm,每 arm 600 步、24 题/更新、BF16、梯度检查点,从同一个 Basic-only 已训 checkpoint(`training_initialization/`)热启动,fresh optimizer。

## 四、闭环游戏评测结果(548 局 test+ood)

| 任务 | 复现 test | 官方 NanoJev test | 复现 ood |
|---|---:|---:|---:|
| Maze | 3/10 | 4/10 | 0/10 |
| Snake | 1/8 | 8/8 | 1/8 |
| ViZDoom Basic | 128/128 | 128/128(完全一致) | 118/128 |
| ViZDoom Predict Position | 37/128 | 27/128(优于官方) | 12/128 |

**Snake 复现偏低的根因分析**(非环境/数值噪声,是模型真实的策略缺陷):
实际决策记录显示,模型对"沿当前方向继续走"给出过高的成功概率估计(如某局连续 4 步选择 east,即使已经贴近边界),却没有正确建模"再走 N 步就会撞墙"。这是训练数据量不足(Snake 训练集仅 400 条问题)导致的空间推理/校准缺陷,一旦触发几乎必然失败,而不是复现误差或硬件数值噪声导致的偶发性波动。

## 五、环境与复现依赖处理

- **uv + 清华 PyPI 镜像**:全局配置 `~/.config/uv/uv.toml` 指向 `https://pypi.tuna.tsinghua.edu.cn/simple`。
- **HuggingFace 镜像**:`HF_ENDPOINT=https://hf-mirror.com`;Xet 加速通道遇 401/超时时改用 `HF_HUB_DISABLE_XET=1` 走传统 LFS。
- **CUDA 兼容性**:机器驱动 550.127.08(对应 CUDA 12.4),torch 2.14.0 默认自带 cu126/cu130/cu132 构建,cu130 因驱动过旧无法初始化 CUDA;改用 `--index-url https://download.pytorch.org/whl/cu126` 安装 `torch==2.14.0+cu126` 后正常。
- **GPU 资源**:8 卡 A100(40GB)共享环境,训练前需确认目标卡(本次用 1、6 号)有足够空闲显存(0.6B 模型全量 AdamW 微调实测峰值显存约 16.9GB)。
- **磁盘空间**:`/home/dataset1` 共享盘曾写满(剩 1.2GB),训练与评测输出改存至 `/tmp/nanojev_runs/`(root 分区,`/tmp` 非持久存储,重启会清空)。
