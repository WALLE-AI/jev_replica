# 结论:代码开源,但完整从零复现有两个外部依赖点无法完全自助

代码本身(MIT License)、训练脚本、评测脚本、已发布的模型权重和数据集(HuggingFace `unified-games-v1`)都是公开的。但如果你想**从零重新生成数据再训练**,链路上有两处依赖外部/非本仓库资源:

## 1. Maze / Snake / Basic 数据依赖付费的 Jev API(闭源)

查看 `scripts/unified_jev_worker.mjs` 可以确认:采集这三类任务的"教师"数据时,代码通过 AI Gateway 调用 `model: 'typesafe-ai/jev'`,也就是 [Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev) 官方托管的闭源模型接口:

- 需要在 `.env` 里配置 `AI_GATEWAY_API_KEY`(`.env.example` 里就这一项)
- 采集命令带 `--budget-usd 2` 这种硬性花费上限,每次调用都记账
- Jev 模型本身**没有开源权重**,只能通过付费 API 调用——这是"复现"里唯一绕不开的黑盒。

## 2. ViZDoom Predict Position 的专家策略依赖第三方仓库的私有 checkpoint

`docs/SONIC_PREDICT_POSITION.md` 里的专家是 [Sonic Doom](https://github.com/thainv0212/sonic_doom) 项目的 CNN+GRU 策略,复现命令里写的是:

```
--checkpoint /path/to/sonic/best_000097758_400416768_reward_0.920.pth
```

这个 `.pth` 权重文件**不在 NanoJev 仓库或 Sonic Doom 仓库的公开发布里**(是本项目作者自己训练/获得的),你需要自己按 Sonic Doom 仓库的方法训练一个,或者联系作者索要。

## 但——如果你的目标只是"训练出同一个模型",不必重新采集数据

由于 HuggingFace 上 **数据集已经连同 Jev/Sonic 生成的训练标签一起发布**了(`C-Tianyu/NanoJev-Data`,`unified-games-v1` 标签,18,760 条问题、896 局专家轨迹全部打包),你可以跳过上面两个黑盒依赖,直接:

1. `snapshot_download` 拿到 `unified-games-v1` 的完整数据快照(已含 hard/soft 标签)
2. 下载 `training_initialization/`(SFT 起点 checkpoint)
3. 直接跑 `docs/SONIC_PREDICT_POSITION.md` 里从 `scripts/train_unified_games.py` 开始的训练命令(SFT 阶段),不需要重新调用 Jev 或 Sonic 专家

这种"用已发布数据重训模型"的路径是**完全可复现**的,唯一动态部分是 GPU/精度环境差异。而"从零采集新数据再训练"这条路径就需要你自己有 Jev API key 和 Sonic Doom 专家权重。
